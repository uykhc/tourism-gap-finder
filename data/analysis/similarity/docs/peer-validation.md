# 유사지역(peer) 선정 검증 보고

최종 갱신 2026-08-25 · 대상 KTO 실제 관광자원 기준 전국 230개 분석 단위 · 우수성·공백 단계는 검증 범위에서 제외

## 최신 검증 — 중복 억제 가중치 반영

인구밀도·도시화율·사업체밀도처럼 같은 도시집적 현상을 반복 측정하는
변수의 합산 가중치를 10%로 제한했다. 6개 하위 요인의 현재 실효 가중치는
설정값과 정확히 일치한다(지역규모 10%, 도시집적 10%, 인구구조 10%,
자연지리 30%, 기후 15%, 산업구조 25%). 산림·농지가 빠져도 그 몫은
자연지리 안의 해안·도서·지형기복에만 재배분된다.

| 검증 항목 | 결과 |
|---|---:|
| 기존 대비 top-15 Jaccard 평균 | 0.838 |
| 기존 대비 top-15 Jaccard 중앙값 | 0.875 |
| top-15가 완전히 같은 지역 | 38/230 |
| 유사도 0.40 이상 peer 평균 | 12.60개 |
| 유사도 0.40 이상 peer 0개 | 4/230 |
| 유사도 0.40 이상 peer 4개 미만 | 18/230 |

대표 결과의 방향은 유지됐다. 경주시는 서산·보령·김제·영천·경산,
평창군은 가평·장수·무주·홍천·영월, 여수시는 창원·광양·순천·동해·포항이
상위권이다. 중복 억제로 순위 일부는 바뀌었지만 전체 후보군은 평균 84%
유지돼 급격한 붕괴는 없었다. 반면 제주 등 고유 지역의 peer 부족과
행정유형 hard filter 문제는 이번 변경의 해결 범위가 아니므로 남아 있다.

아래 1~7절은 2026-08-17 이전 변수 구성으로 수행한 검증 기록이며 현재
수치로 해석하지 않는다. 현재 변수 계약과 데이터 상태는 8절을 기준으로 한다.

## 0. 이전 구현에서 무엇을 검증했나

"구조적 여건이 비슷한 지역"이 실제로 비슷하게 뽑히는지만 본다.
정답표가 없는 문제이므로 아래 네 가지로 우회 검증했다.

1. 무작위 대비 얼마나 가까운가 (변별력)
2. 서로를 유사지역으로 인정하는가 (상호성)
3. 가중치를 흔들어도 유지되는가 (안정성)
4. 사람이 보기에 말이 되는가 (안면타당도)

**사용 변수** — 인구·면적·인구밀도(log), 해안/도서 여부, 농가·임가·어가 비율,
최근접 대도시 직선거리(log), 평균연령, 평균가구원수.
전부 SGIS 2020 총조사 + 지리적 사실이며, **관광 콘텐츠나 관광 성과는 하나도 포함되지 않는다.**

## 1. 변별력 — 무작위보다 확실히 가깝다

| 지표 | peer 15개 평균 | 무작위 기대값 | 판정 |
|---|---|---|---|
| 해안 여부 일치율 | **88.6%** | 57.0% | 양호 |
| 도서 여부 일치율 | **96.4%** | 90.9% | 양호 |
| 인구 배율 중앙값 | **1.45배** | 2.96배 | 양호 |
| 면적 배율 중앙값 | **1.48배** | 3.84배 | 양호 |

해안 여부는 우연이라면 57%가 나와야 하는데 88.6%다. 인구·면적은
무작위로 두 지역을 고르면 3~4배 차이가 나지만, peer끼리는 1.5배 안쪽이다.

전국 무작위 쌍의 가중거리 중앙값은 1.256인 반면, peer는 대부분 0.2~0.6 구간에 있다.

## 2. 상호성 — 66.8%

A의 peer로 뽑힌 B가, B를 기준으로 다시 계산했을 때도 A를 peer로 포함하는 비율이 **66.8%**다.
k=15 고정 kNN에서 상호성이 100%가 될 수는 없다(밀집 지역은 서로를 밀어낸다).
2/3 수준이면 거리 구조가 일관적이라고 볼 수 있다.

## 3. 안정성 — 가중치를 크게 흔들어도 top-15가 90% 유지

| 가중치 변경 | top-15 겹침 |
|---|---|
| 기본 (규모30/지리30/접근20/인구20) | — |
| 균등 (25/25/25/25) | **93.0%** |
| 규모 강조 (50/20/15/15) | **89.0%** |

가중치는 아직 확정 안 된 값인데, 그걸 크게 바꿔도 결과가 거의 그대로다.
**즉 현재 peer 결과는 특정 가중치 선택에 의존하지 않는다.** 튜닝 부담이 낮다는 뜻이기도 하다.

## 4. 안면타당도 — 스팟체크

```
경상북도 울릉군  -> 남해군, 진도군, 양양군, 하동군, 강화군          도서·해안 소규모 군
인천 옹진군      -> 진도군, 신안군, 남해군, 완도군, 강화군          도서 군만 정확히 모임
충청남도 당진시  -> 서산시(0.90), 순천시, 군산시, 여수시, 사천시    중소 해안 산업도시
경상북도 안동시  -> 제천시, 김천시, 영주시, 충주시, 남원시          내륙 중소도시
경기도 수원시    -> 성남시, 고양시, 안양시, 의정부시, 전주시        대도시권 대규모 시
경기도 가평군    -> 연천군, 양평군, 거창군, 창녕군, 함안군          수도권 근교 농촌 군
강원 태백시      -> 영주시, 제천시, 남원시, 문경시, 안동시          내륙 산간 소도시
대구 달성군      -> 칠곡군, 기장군, 진천군, 울주군, 음성군          대도시 인접 준도시 군
세종특별자치시   -> 달성군, 양산시, 구미시, 김해시, 경산시          신도시·젊은 인구
```

도서 지역이 도서끼리, 해안 군이 해안 군끼리, 대도시 근교 군이 근교 군끼리 모인다.
군에 광역시 자치구가 섞이는 사고는 없다(동일 행정유형 필터가 작동).

가장 조밀하게 붙은 쌍도 납득 가능하다 — 당진시↔서산시(0.90), 부산 서구↔영도구(0.93),
서울 동대문구↔동작구(0.94).

## 5. 확인된 한계 세 가지

### L1. 자치구 간 변별력이 약하다 (가장 중요)

서울 25개 자치구의 상호 유사도 중앙값이 **0.67**로, 서로 거의 구분되지 않는다.
현재 변수(인구·면적·밀도·연령·가구)로는 강남구와 은평구가 비슷해 보이기 때문이다.

```
서울 강남구 -> 은평구(0.84), 대구 달서구(0.84), 영등포구(0.81), 성북구(0.80), 노원구(0.79)
```

인구 규모와 밀도는 실제로 비슷하지만, 상업 집적도·소득·업무지구 성격이 전혀 반영되지 않았다.
**자치구를 대상으로 한 분석은 현 단계에서 신뢰도가 낮다.**
군·시는 농림어가 비율과 해안 여부가 강하게 작동해 훨씬 잘 갈린다.

### L2. 고유한 지역은 peer group을 15개까지 채우면 질이 급락한다

15번째 peer의 유사도가 0.40 미만인 지역이 **21곳(9%)** 있다.

```
완도군, 신안군, 울릉군, 옹진군, 청도군, 영종구, 진도군, 제주시, 남해군, 서귀포시
```

제주시는 2위(서귀포시 0.64)까지는 좋지만 3위부터 0.28로 떨어진다.
울릉군은 1위조차 0.32다. 비교 대상이 실제로 없는 지역들이다.

→ **k를 고정하지 말고 유사도 하한(예: 0.4)을 두고 잘라내는 편이 낫다.**
peer가 3곳뿐이면 3곳만 쓰고 그 사실을 알리는 쪽이 정직하다.

### L3. 접근성이 직선거리 proxy다

대도시까지의 직선거리를 쓴다. 태백시처럼 거리는 가까워도 산악 지형 때문에
실제 이동시간이 훨씬 긴 지역은 접근성이 과대평가된다.
가중치 20%라 영향이 제한적이지만, Kakao Mobility 이동시간으로 바꿀 여지가 있다.

## 6. 결론

**시·군 단위 유사지역 선정은 프로토타입 용도로 쓸 만하다.**

- 무작위 대비 변별력이 뚜렷하고(해안 88.6% vs 57%, 인구 1.45배 vs 2.96배)
- 가중치를 크게 흔들어도 90% 유지되며
- 스팟체크 결과가 직관과 어긋나지 않는다

**자치구 단위는 현재 변수로는 부족하다.** 상업·업무 성격을 나타내는 변수
(사업체 수, 종사자 수 — SGIS `corp_cnt`/`employee_cnt`로 확보 가능)를 넣어야 한다.

## 7. 우선 개선 항목

1. **자치구 변별 변수 추가** — SGIS 사업체·종사자 수 (이미 같은 API에서 나온다)
2. **peer 유사도 하한 도입** — k 고정 대신 하한 미달 시 잘라내고 개수를 알림
3. 접근성을 이동시간으로 교체 (Phase 2)

### 재현 방법

```bash
tourgap --region 당진시 --explain          # 구조 변수 원본값 비교
tourgap --region 울릉군 --no-save          # 고유 지역 사례
tourgap --region 강남구 --no-save          # 자치구 한계 사례
```

## 8. 2026-08-24 구현 갱신 — 17개 구조 변수 계약

`PeerFinder` 구현은 `contracts.PEER_COLUMNS` 검증을 통과하는
`tourgap.peers.TourgapPeerFinder`로 제공한다. 반환 필수 컬럼은
`rank`, `region_id`, `similarity`이며, target 지역은 제외하고 유사도 하한
기본값 0.40과 기본 최대 15개를 적용한다.

최종 스키마는 17개로 유지하고, 중복 영향을 줄이기 위해 6개 하위 요인의
총 가중치를 고정했다.

| 하위 요인(가중치) | 변수 |
|---|---|
| 지역규모(10%) | `area_km2`, `total_population` |
| 도시집적(10%) | `population_density`, `urbanization_ratio`, `business_density` |
| 인구구조(10%) | `average_age` |
| 자연지리(30%) | `coastal_dummy`, `island_ratio`, `forest_ratio`, `farmland_ratio`, `terrain_relief` |
| 기후(15%) | `annual_mean_temperature`, `annual_temperature_range`, `annual_precipitation` |
| 산업구조(25%) | `manufacturing_worker_ratio`, `construction_logistics_worker_ratio`, `knowledge_public_service_worker_ratio` |

로그 변환 대상은 `area_km2`, `total_population`, `population_density`,
`business_density`, `annual_precipitation`, `terrain_relief`이다. 표준화 후
pairwise 거리 계산 시 양쪽 지역 모두 값이 있는 변수만 사용한다. 요인 내
일부 변수가 없으면 그 요인의 가중치를 나머지 변수끼리 재배분한다.

현재 레포에 준비된 실데이터/정적참조는 SGIS 인구·면적, 평균연령,
도시화지역 경계, 해안·도서 정적 테이블, 2024년 SGIS 사업체통계,
국가토지피복통계 기반 산림·농지 비율, 한반도 90m DEM 기반 지형 기복이다.
다음 원자료는 임의 대체하지 않고 정적 CSV 또는 실제 API 응답 fixture로만 쓴다.

| 변수 | 필요한 원자료 | 현재 처리 |
|---|---|---|
| `urbanization_ratio` | SGIS 도시화지역 경계(2024-06-30) | `UA_AREA` 합계 / SGIS 행정구역 면적 구현 완료 |
| `forest_ratio`, `farmland_ratio` | 2025년(2024년 기준) 국가토지피복통계 토지피복지도현황 | `data/processed/land_cover_by_region.csv` 생성 완료 |
| `terrain_relief` | 국토지리정보원 한반도 90m DEM | 시군구 경계 내 고도 P90-P10 산출 완료 |
| 기후 3개 변수 | 기상청 기상자료개방포털 1991~2020 기후평년값 파일셋 | `data/processed/kma_climate_normals_by_region.csv` 생성 완료 |
| 산업 4개 변수 | SGIS `company.json`, 제11차 산업분류 | 2024년 시군구 응답 수집·집계 완료 |

공간 원자료와 기후평년값 원본은 Git에 넣지 않는다.
`tourgap.data_sources.RawDataPaths`에 경계, 도시화경계, 해안선, 토지피복,
DEM, 기후평년값 파일 경로를 명시하고 `require_existing_paths()`로 입력
계약을 먼저 검증한다. 토지피복은 일반구를 모 시로 합산하고, 2026년 인천
분할 지역은 보정표로 기존 구 면적을 배분해 `proxy`로 표시한다. 기후평년값은
OpenAPI 일자료 재계산이 아니라 기상청 공식 1991~2020 파일셋을 사용한다.
현재 시군구별 기후 feature는 관측소 평년값을 시군구 중심점 기준 가까운
관측소 3개 역거리 제곱으로 보간한 정적 CSV를 재사용한다.
