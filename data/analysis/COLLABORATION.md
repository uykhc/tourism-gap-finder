# 분석 모듈 협업 기준

## 현재 구조

- `calculation`: 관광·공공 데이터 수집, 콘텐츠 공급과 수요 분석, 관광 공백 및 AI 리포트 생성
- `similarity`: 관광 성과와 공급을 제외한 구조적 특성으로 유사 지역 후보 선정
- `evaluation`: 방문자와 관광 수요를 이용한 성과 평가 및 benchmark 선정
- `contracts`: 향후 공용 타입과 지역 마스터를 둘 위치이며, 현재 설치 가능한 패키지는 아님

각 분석 패키지는 독립 CLI로 실행합니다. API는 `apps/api/app/data/artifacts`의
샘플 산출물을 기본으로 읽고, 실제 분석 결과는 `ANALYSIS_ARTIFACT_ROOT`로 지정합니다.

## 공통 원칙

1. 지역 조인 키는 법정동 시군구 코드 5자리 `region_id`를 사용합니다. 지역명만으로 조인하지 않습니다.
2. 유사도 계산에는 관광 콘텐츠 수, 방문자, 체류, 소비 등 관광 성과·공급 변수를 사용하지 않습니다.
3. 결측을 임의로 0으로 바꾸지 않습니다. 0과 자료 없음은 구분합니다.
4. 데이터 출처는 `real`, `proxy`, `static_reference`, `mock` 중 하나로 표시합니다.
5. 분석 결과는 비교와 후보 선별의 근거로 사용하며 인과관계나 사업 성공을 단정하지 않습니다.

## 변경 원칙

- 패키지의 공개 CLI, JSON 필드 또는 `region_id` 처리 방식을 바꾸면 이를 소비하는 분석 단계와 API를 함께 확인합니다.
- 외부 API 키와 데이터베이스 접속 정보는 환경 변수로만 관리하고 Git이나 브라우저 코드에 넣지 않습니다.
- 분석 방법이나 지표를 바꾸면 관련 설정, 문서와 재현 테스트를 함께 갱신합니다.
